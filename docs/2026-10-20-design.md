# kosif.org 콘텐츠 조회수 대시보드 — 설계 (2026-10-20 승인)

## 목적
국문 홈페이지(kosif.org) 게시판·글별 조회수를 링크 하나로 언제든 확인. 누적 / 올해 쓴 글 / 올해 생긴 조회수 세 가지 관점.

## 제약
- **국문 홈페이지(서버)는 건드리지 않는다.** 조회수(wr_hit)는 글 보기 페이지에만 표시되고, 열면 +1 된다(세션당 1회, 화면 표시값은 +1 이후 값).
- 대시보드 수치는 정확해야 한다 → 우리가 연 횟수(visits)를 글마다 기록해 빼준다.
- 홈페이지에 보이는 조회수 부풀림은 최소화 → **매월 1일 1회** 수집(+수동 실행 버튼).

## 구성
1. `collector/collect.py` (파이썬 표준 라이브러리만)
   - 대상: 공개 게시판 18개(s1_7 온라인문의·s4_4 비공개 제외).
   - 글 번호 찾기: 공개 목록 페이지의 wr_id + 기존에 알던 번호 → 게시판별 1 ~ (최대번호+15)까지 차례로 확인. 없는 번호는 조회수 영향 없음.
   - 한 번의 실행 = 한 세션(쿠키 유지) → 글마다 정확히 1번만 +1.
   - 실제 조회수 = 표시값 − 누적 방문수(이번 방문 포함).
   - 동시 4개, 요청 사이 짧은 대기.
2. 데이터(`data/`)
   - `posts.json`: 글별 {게시판, 번호, 제목, 분류, 작성일, visits, 최근 실제 조회수}.
   - `snapshots/<날짜>.json`: 그날 글별 실제 조회수. `snapshots/index.json`: 날짜 목록 + 갱신 시각.
   - 초기값: 2026-10-20 1차 수집으로 모든 기존 글 visits=1(s4_2/105는 2). 구축 당일 기준점 수집 1회.
3. `index.html` 대시보드(정적, GitHub Pages)
   - 탭: 누적 / 올해 쓴 글 / 올해 생긴 조회수(+월별 증가 그래프).
   - 게시판별 막대그래프·표, 전체 글 목록(검색·게시판 필터·정렬·글 링크).
   - "조회수 안 쌓이는 게시판"(CDP Resources·정기간행물) 회색 표시.
   - `noindex` + `robots.txt`.
4. ~~GitHub Actions~~ → **변경(2026-10-20)**: 카페24가 해외 데이터센터에 로봇 확인 페이지를 띄워 Actions에서 수집 불가(우회하지 않음). 대신 KoSIF PC 작업 스케줄러가 매월 1일 **10:00**에 `scripts/run_collect.ps1` 실행(꺼져 있었으면 켜지는 대로), 수집 → 커밋·푸시 → Pages 반영.

## "올해 생긴 조회수" 계산
- 기준 = 올해 들어 첫 스냅샷(2026년은 구축일). 기준 이후 새로 생긴 글은 전체 조회수가 올해분.
- 월별 증가 = 연속된 스냅샷의 차이를 (뒤 스냅샷 날짜 − 1일)이 속한 달에 배정(11/1 수집분 = 10월).

## 공개 범위
공개 저장소 kosif2007/kosif-content-stats. 들어가는 정보는 홈페이지에 이미 공개된 제목·번호·작성일·조회수뿐.
